# Update Python to 3.12

## Goal

Update the project Python baseline and container runtime to Python 3.12 so local dependency resolution and Docker builds target the same supported version.

## Requirements

* Set project Python requirement to Python 3.12.
* Update Docker build and runtime images from Python 3.9 to Python 3.12.
* Refresh uv-managed lock/export artifacts so dependency metadata matches the new Python baseline.
* Do not change application behavior unless Python 3.12 compatibility requires it.

## Acceptance Criteria

* [x] `pyproject.toml` declares Python 3.12 as the minimum supported version.
* [x] `uv.lock` is refreshed for the new Python requirement.
* [x] `requirements.txt` is regenerated from the refreshed lock file if dependency markers change.
* [x] `Dockerfile` uses Python 3.12 for both builder and runtime stages.
* [x] Project verification commands run through `uv run` successfully where practical.

## Definition of Done

* Dependency resolution succeeds with `uv sync --locked`.
* Python import/compile verification succeeds through `uv run`.
* Changes are limited to Python version and generated dependency metadata unless compatibility fixes are required.

## Technical Approach

Use the existing uv workflow: update `pyproject.toml`, run uv lock/export commands, update Docker base images, then verify with the project's uv-based commands.

## Decision (ADR-lite)

**Context**: The repo currently declares `requires-python = ">=3.9"` while the Dockerfile uses `python:3.9-slim`.

**Decision**: Treat Python 3.12 as the new project minimum and runtime target, not merely an additional supported version.

**Consequences**: Older Python versions will no longer be supported by project metadata. Docker builds and local uv environments will resolve against the Python 3.12 baseline.

## Out of Scope

* Refactoring application code unrelated to Python 3.12 compatibility.
* Changing published app version or release notes.

## Technical Notes

* `pyproject.toml` contains the project Python requirement.
* `uv.lock` contains the locked Python requirement and dependency markers.
* `requirements.txt` is generated by `uv export --locked --no-dev --no-hashes --output-file requirements.txt`.
* Initial inspection found `Dockerfile` using `python:3.9-slim` for both stages.
* Verification completed with uv selecting local CPython 3.13.7 under the new `>=3.12` project constraint.
* Starlette's current `Jinja2Templates` no longer accepts the old `autoescape=` keyword; app-owned autoescaped templates now use `app.shared.template_factory.create_templates`.
